# 維護順序與收斂完成條件

更新：2026-10-24。資料統計與已發布基準只維護於[文件入口](README.md)。目前以穩定運作及降低維護負擔為主；保留現有靜態網站、資料來源與精確查證規則，不把所有可選改善都當成下一批必做工作。

## 日常只走三條路

| 順序 | 何時需要處理 | 完成標準 |
|---|---|---|
| 1. 修復實際故障 | 自然排程、必要檢查、正式部署驗收失敗，或取得可重現的安全／資料保護問題 | 保留可靠資料，修正根因及必要回歸，經 PR／必要 gate／正式站驗收。不能用重跑成功掩蓋原因。 |
| 2. 例行維護 | 依既有週期出現安全公告或相容性更新提案 | 依[依賴維護流程](依賴與Actions維護.md)審查，不為追最新版本一次合併所有提案；保留 hash lock、完整 SHA、Windows 及 Linux gate。 |
| 3. 有新證據才補資料 | 來源新增版本專用原文、固定修訂、明示資料庫連結或完整系列證據 | 精確綁定作品／季別／cour，保留原文、來源及適用授權，更新防覆寫規則後發布。只有作品身分或版本範圍仍歧義時才請使用者判斷。 |

已完成的安全、鍵盤、搜尋與分享修補不再列為待辦。每批只處理能清楚驗收的範圍；若未取得新證據，就記錄停止條件並結束該批，不以新增功能或文件延長工作。

## 保留查證缺口，不反覆重查

數量與逐筆清單由[資料補齊入口](README.md#資料補齊入口)連入，下表只列重新啟動的條件。

| 類別 | 停止／重啟條件 |
|---|---|
| 當季四筆簡介及其餘缺漏 | 缺對應季別／cour 原文；維基新增集數資訊不等於有簡介。取得可引用的版本專用介紹後才重啟。 |
| 班長／學校卡片範圍 | 班長不能借利根川母條目；學校的既有 9 話只限整理整頓編。取得完整版本證據才修改。2019 夏屁屁偵探已確認第三系列，不再猜系列。 |
| 奇喵的畫家 Bangumi 連結 | 既有完整目錄與搜尋沒有原名精確候選；只在出現新的明示連結或身分證據後重查，不猜 ID。 |
| AniList 可選連結 | API 連線程式與啟用開關維持退役；依新的明示對應證據經 PR 補入。其餘名稱、日期、重複映射及既有連結差異見[本批清單](anilist-links-2026-10-24/README.md)，需補足對應版本證據才採用。 |
| 平台權限、憑證與備份 | 需平台端有效設定或完成紀錄才能核實；未核實不等同未啟用。認證或權限拒絕時記錄當次錯誤，不換工具或代理繞過；不為驗證直接改 Cloudinary 或重寫 Git 歷史。 |

不得自行生成簡介、借前季／母條目／不同 cour、覆寫可靠內容，或把預定總數當已播進度。來源限制以當次實效設定及 HTTP 結果為準。

## 查實際狀態，不重做已完成驗證

當次 PR、Actions 與正式站版本的查詢方式見[文件入口](README.md#資料與發布基準)，已完成事故與排程案例見[歷史索引](archive/README.md#事故與過渡操作)。不把舊文件的「等下次排程」重新列為待辦，也不以固定測試總數代替這批檢查。

真實來源故障、超額持久待辦、C 到期通知及 retention 刪除等情境，只在正式案例出現時核對。工作成功不等於已觀察到每種情境；日誌或 artifact 不能存取時明列界線，不因 job 綠燈宣稱已讀取內容。不建立假 Issue、不發測試留言或通知、不手動觸發排程或刪圖補證據。

## 暫不擴充的提案

CSP 樣式收緊、Firefox／WebKit／真實手機驗收及更多效能優化保留於[既有改善計畫](CSP與跨瀏覽器改善計畫.md)與[開發手冊](開發與測試.md)。後端 socket timeout 仍不等於嚴格整段傳輸期限；第三方渲染／剪貼簿也須區分 UI 復原與真正取消底層工作。只有實際風險、量測或使用需求能支持變更時，才另開有界工作，不增加必要資料來源、常駐服務或平台。

## 每批收斂完成條件

1. 同步最新 main，確認這批只改已授權的範圍，可靠資料與原始證據都保留。
2. 執行與變更相符的本地檢查，通過 PR 的 Linux／Windows／required `quality` 及預覽；文件變更檢查連結與現況，不另寫低價值測試。
3. 合併後正式站公開檔案與發布版本一致，瀏覽器驗收完成，工作樹乾淨；結果集中於該 PR。
4. 有新事實才更新唯一現況入口；已完成工作移出待辦，缺證據／權限者標明重啟條件。這一批未完成的候選提案不自動成為下一批承諾。
