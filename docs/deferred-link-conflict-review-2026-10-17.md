# 再次檢查：暫缺來源連結不能當作衝突已解決

基準 main `6de6bfb867f8e3bfa4e253d8765a85f5ec4310d4`（PR #52）。本輪檢查來源核對、審核待辦、日期提醒與通知流程的邊界情況，找到一個可重現的待辦證據遺失問題。

## 觸發條件

同一作品曾有本地 AniList ID 20、來源明示 ID 21，因通知額度而保存在持久待辦。下次來源暫時沒有明示連結，或者該卡片消失／作品身分變動時，核對仍可成功讀完整季度頁，候選集合卻只剩本地 ID 20。舊判斷只檢查「只剩一個 ID、季度頁讀取成功」，便把先前衝突當作已解決並刪除待辦，沒有取得明確的解決證據。

## 修正

唯讀核對報告每筆季度觀察增加 `source_link_observation`，保留本次來源卡片的精確身分核對結果、時間，以及原頁明示的 AniList ID。這裡的 `verified` 指卡片與作品身分符合；若原頁沒提供 AniList，`anilist_id` 仍為 null，不能視為已驗證一個來源連結。卡片／原名／中文名不符合，或來源明示 BG ID 與既有綁定衝突時，不採其 AniList 連結。

自動清除連結衝突待辦時，除了只剩唯一 ID、原相關季度頁成功取得外，現在必須每個原相關季度都具有本次精確作品身分對應、非空查證時間，且來源明示同一 AniList ID。缺連結、缺卡片、換身分、缺日期、不同 ID、只完成部分季度或舊報告沒有新增欄位時，一律保留原證據。若來源確實全部一致，仍可正常清除。

本輪沒有更改公開資料、外部 ID 或計數值，也沒有改變指定審核者的 A/B/C 規則；留言仍不直接修改公開資料。
