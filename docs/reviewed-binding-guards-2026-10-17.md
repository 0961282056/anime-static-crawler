# 重新審查：人工來源綁定及寫入驗證

基準 main `e6c81ff2b1ad108c335a0640f4ce7e124c461a28`（PR #51）。本輪重新檢查資料儲存邊界、集數刷新／來源綁定、前端請求失敗處理及自動發布流程，確認並修正以下兩個可重現問題。

## 原文名稱變更可能失去人工審查規則

原先只在中文名稱變更時檢查人工集數或官方簡介規則是否失去綁定。若來源保留中文名、改動原文名，卡片可以寫入，原有人工範圍或官方簡介也會遺失；即使輸入同時帶有集數 metadata，也沒有擋下。

修正為先完成相同身分的欄位暫缺回填，再檢查實際將寫入的完整身分。只要原先存在人工集數或官方簡介審查規則，而新身分失去對應，就停止整個季度寫入並保留原檔；需要先審查新身分及更新精確規則。已知 ID 衝突防護與三筆已確認中文譯名更新仍照原規則處理。

來源暫時沒有提供原名或外部 ID 時，會先保留舊欄位與證據，不誤認為作品改版。這裡只修正資料保護，沒有自行判斷任何新版本或集數範圍。

## 複製後修改的模型可能跳過巢狀驗證

`DataRepository.write_quarter()` 原先信任傳入的 `Anime` 實例。Pydantic 的 `model_copy(update=...)` 可以產生未驗證的巢狀資料，因此例如「已播10、總數由12改為6」的物件仍可能寫入 JSON，讓下一次讀取才失敗。

修正為在寫入邊界把模型欄位序列化後重新驗證，讓巢狀集數與簡介證據一致性檢查確實執行；錯誤仍以既有 `DataContractError` 回報，不輸出完整資料內容、不覆寫原檔。既有摘要 ID 不一致原本已會在後段阻擋，本輪另確認能提前於單筆契約驗證攔下。
