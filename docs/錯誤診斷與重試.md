# 錯誤診斷與重試

## 先看這些資訊

本機命令 `generate_static.py`、`manage.py` 失敗時會以非零狀態結束，並列出錯誤代碼、階段、例外類型、原因、位置及處理建議。位置依失敗步驟包含季度、檔案、動畫名稱或來源卡片索引；沒有相關資訊時不會捏造。

GitHub Actions 會把命令錯誤加入 annotation 與執行摘要。跨工作傳遞到 Discord 的內容僅包含已知代碼與階段對應的說明，原始例外、憑證及檔案內容不會透過 job output 傳送。安裝依賴、預檢、artifact 或 runner 本身失敗時可能只有 `PIPELINE` 與失敗步驟，仍需查看該步驟第一個錯誤。取消或 runner 強制終止也可能沒有完整摘要。

一般成功日誌只有步驟耗時、季度有效筆數、解析失敗數與有無變更，不逐筆列印健康資料。若圖片處理先失敗、儲存快取也失敗，最初的圖片錯誤會保留，快取錯誤列為附加資訊。

## 後端錯誤代碼

| 代碼 | 原因與下一步 |
|---|---|
| `CONFIGURATION` | 環境變數缺失或超出允許範圍。確認變數名稱、數值與設定位置後重跑。 |
| `SOURCE_NOT_FOUND` | 來源季度回傳 404。未來季度未公開會正常略過；歷史季度需先調查來源。 |
| `SOURCE_FETCH` | 來源 HTTP／網路故障。查看狀態碼、DNS 與連線，暫時故障可稍後重試。 |
| `SOURCE_PARSE` | 來源 selector 或卡片不符合契約。比對 HTML、修復 parser，先執行 canary。 |
| `IMAGE_QUOTA` | Cloudinary 用量達門檻。查看用量，必要清理先做 retention dry-run；不會自動刪圖。 |
| `IMAGE_STORE` | 圖片下載、格式驗證或 Cloudinary 失敗。查看圖片主機、HTTP、權限與用量。 |
| `DATA_CONTRACT` | JSON、欄位或品質 gate 失敗。訊息指出季度、筆次、欄位或數量差異。修復來源後重跑，不放寬品質門檻。 |
| `FILE_PERMISSION` | 檔案存取遭拒。查看路徑權限、檔案占用；在 Windows 可關閉使用該輸出目錄的程式後重試。 |
| `FILE_IO` | 磁碟、檔案不存在或其他讀寫故障。查看路徑與剩餘空間，保留備份。 |
| `NOTIFICATION` | Discord 未送達。查看 webhook 設定、HTTP 與網路。這不代表資料爬取一定失敗。 |
| `PR_HEAD_CHANGED` | PR head 已改變。重新取得 main 並重新產生、驗證資料。 |
| `PR_CLOSED` | PR 關閉但未合併。查看關閉原因後再重新執行資料更新。 |
| `PR_CHECK_FAILED` | 必要檢查失敗或取消。開啟訊息中的 check 連結，修復第一個錯誤。 |
| `PR_TIMEOUT` | 30 分鐘合併等待耗盡。查看必要檢查、分支規則與 GitHub API 狀態。 |
| `PIPELINE` | 命令外的工作流程失敗。查看標示的步驟與 Actions 日誌。 |
| `UNEXPECTED` | 非預期程式問題。查看遮蔽敏感值後的 traceback，修復後跑回歸測試。 |

欄位驗證摘要最多顯示前 20 個問題，並標示其餘問題數量；不顯示原始 input。診斷主訊息長度有上限，避免 CI 摘要與通知被巨大例外內容塞滿。

## 重試與資料保護

- 來源與圖片 GET／HEAD 最多重試 3 次，只有已設定的暫時性狀態會自動重試；單次 `Retry-After` 等待上限 30 秒，退避上限 10 秒。
- `REQUEST_TIMEOUT_SECONDS`、`IMAGE_TIMEOUT_SECONDS` 可設 1–120 秒，預設 15 秒。Cloudinary 配額查詢與上傳也會傳入對應逾時。這是各網路操作的逾時，整體工作仍由 Actions job timeout 限制。
- 不自動重試 Cloudinary 上傳或 Discord POST，避免無意義的重複寫入或通知。
- 系統故障會取消尚未開始的卡片工作；已開始的工作仍需完成或發生逾時，然後保存快取。
- 原子檔案寫入失敗會保留原檔；如果清理也失敗，附加資訊會指出暫存位置。
- 靜態檔案 swap 失敗會嘗試還原。還原也失敗時會保留並指出備份目錄；不要先刪除 `.static.backup-*`。

## 前端資料錯誤

| 代碼 | 可見說明與操作 |
|---|---|
| `NETWORK` | 檢查網路後重新載入。 |
| `FETCH_TIMEOUT` | 資料請求逾時，可稍後重新載入。 |
| `HTTP_404` | 季度資料不存在，確認是否已發布。 |
| `HTTP_429` | 服務忙碌；有限重試耗盡後稍後再試。 |
| `HTTP_5XX` | 服務暫時異常；有限重試耗盡後稍後再試。 |
| `JSON_PARSE` | 回應不是有效 JSON，聯絡維護者查看資料或路由。 |
| `DATA_SCHEMA` | 清單或動畫欄位格式錯誤，訊息會指出筆次。 |

前端最多自動重試 2 次，單次請求 15 秒，逾時包含 JSON body 讀取。取消舊季度請求不顯示錯誤。404、非法 JSON 與資料格式錯誤不自動重試，也不放入快取。

同季度重新載入失敗會保留並標示上次成功資料，切換不同季度先清除舊資料。按「重新載入」會跳過該季度的快取。瀏覽器無法儲存偏好時顯示提示，關閉後本次頁面不會反覆出現。

分享圖片錯誤另外使用 `SHARE_IMAGE_URL`、`SHARE_IMAGE_LOAD`、`SHARE_RENDERER_TIMEOUT`、`SHARE_RENDERER_NETWORK`、`SHARE_RENDERER`、`SHARE_EXPORT` 分類。失敗訊息提供原因與建議，按鈕會還原，清單保留以便重試；單張圖片等待上限 15 秒。剪貼簿拒絕會使用下載備案，文字複製失敗則提示手動複製。

## 本機追查

```powershell
$env:BUILD_ONLY = 'true'
$env:LOG_LEVEL = 'DEBUG'
.\.venv\Scripts\python.exe generate_static.py
.\.venv\Scripts\python.exe manage.py validate-all
Remove-Item Env:BUILD_ONLY
Remove-Item Env:LOG_LEVEL
```

DEBUG 會提供更多技術細節。日誌與報告會遮蔽已設定的 token、API key、secret、webhook、URL 帳密與查詢參數；分享日誌前仍需確認其他由來源或第三方帶入的內容。不要把真實憑證貼到 Git 或錯誤回報。
