# 集數與播出狀態

動畫卡片新增正篇集數、播出狀態、來源與確認時間；側欄增加播出狀態篩選。範圍是來源所連結的一筆動畫資料庫條目，不是漫畫、真人劇或整個系列。跨季度的同一季仍可共用資料庫 ID。

## 網站顯示

| 資料情況 | 卡片文字 |
|---|---|
| 已播 8 集，確認總數 12 集 | 已播 8／12 集 |
| 已播 8 集，資料庫列預定 12 集 | 已播 8 集／預定 12 集 |
| 未知總數 | 已播 8 集／總集數未定 |
| 完整 12 集且有播畢依據 | 全 12 集 · 本季已播畢 |
| 總數已知但進度不足以判斷 | 共／預定 12 集／進度待確認 |
| 未取得集數 | 集數待確認 · 狀態待確認 |
| 來源更新失敗 | 保留最後確認值，附「更新未成功，資料可能落後」 |

「集數來源與確認時間」可展開查看查詢時間、判斷說明與 Bangumi 正篇集目。未知值使用 `null`，不會用 `0` 代替。

## 資料來源與判斷

- 新番清單、封面、星期、時間與簡介繼續使用 acgsecrets.hk。
- 從來源卡片的資料庫連結讀取 `external_ids.bangumi` 和 `external_ids.anilist`。原本 `bangumi_id` 仍是 acgsecrets 卡片 ID，禁止拿來呼叫 Bangumi API。
- 優先使用 Bangumi API；查詢失敗時以 Bangumi 公開頁面（`bangumi.tv`）備援。兩者使用相同的集數與播畢判斷，不會由頁面「已放送」圖示推算進度。AniList ID 保留作參考，API 連線程式已退役；維基百科、萌娘百科與官方公告目前作人工交叉查證，沒有把混合媒體／多季頁面加入自動回填。
- 查詢 `/v0/subjects/{id}` 與分頁 `/v0/episodes?subject_id={id}&type=0`；驗證條目 ID、動畫類型與來源原名。名稱有歧義時不模糊配對。
- 頁面備援讀取 `/subject/{id}` 的話數／播出日期及 `/subject/{id}/ep` 的正篇集目，驗證頁首 ID 與動畫分類。頁面登入牆、結構改變、未辨識的正篇分類、分頁集目清單均不當成完整資料；備援無法確認時保留上次資料。來源 URL 仍使用 `bgm.tv` 的標準條目網址，說明欄標示頁面備援。
- 總集數取 `eps`。`total_episodes` 是資料庫章節數，不能當正篇總數。
- 只計入正篇 `type=0`，依集目 ID 去重，排除非整數集號的回顧篇與特殊集。缺日期／集號斷裂時不把已知下限當精確進度。
- 已播集數依日本日期計算；當日集目尚無可靠播出時刻，暫不計入。這是保守的首播日期進度，可落後一天，不代表台灣平台上架進度。
- 「本季已播畢」需同時有：已過的明確結束日期、完整正篇清單、所有正篇日期已過，以及正篇數等於總話數。集數相等本身不代表播畢。
- 播出中依未來集目／近期尚未完成的集目判斷。缺乏足夠證據時使用未知；暫停和取消狀態保留於模型與介面，但不從停止更新推算。
- 預定集數在完整播畢核對前顯示「預定」。本季播畢不等於全系列完結。

Bangumi API 契約：https://github.com/bangumi/api/blob/master/open-api/v0.yaml

## 保存與更新

`Anime` 新增 `original_name`、`external_ids` 及可空的 `episodes`；舊季度 JSON 可繼續讀取。集數欄位集中在 `episodes`，包含總數、已播、狀態、計數狀態、查詢狀態、來源 URL、成功確認時間、嘗試時間與結束日期。

爬取基本資料後會合併同一卡片 ID 的舊集數；如果外部動畫 ID 改變，就清除舊補充資料重新確認，避免套用到另一季。回填時來源連結或原名暫時缺漏，保留既有值。補充來源失敗、資料缺漏或進度倒退不會覆寫最後有效值；來源衝突保留最後確認值與確認時間，播出狀態標示待核對。

每日優先處理連載、未首播、當季／未來季度狀態未知及結束後第一週的作品；跨季同一作品以最新收錄季度判定，歷史長篇仍可每日優先。歷史未知每 30 天、歷史完結每 90 天，以精確身分分散首次到期；歷史來源失敗每七天重試。季度 JSON 是持久快取，不依賴臨時 runner。

每輪預設最多 240 次補充請求、約 600 秒請求時間預算；有歷史到期時，保留最多 64 次請求及四分之一剩餘時間，未用完額度再交回每日工作。來源變慢、失敗或預算不足時可能延後，不保證每天重查全部作品。API 每頁 200 筆、最多 20 頁，頁面備援每筆最多 2 次請求，兩者共用至少 0.5 秒間隔及預算；端點斷路器會在 429、5xx 或連線錯誤時停止該端點請求，保留其他可用來源與最後成功值。

錢天堂由專用 NHK 完整目錄抽取器每七天核對，失敗隔一天重試；不計當日／未來節目，不由目錄數推論總數或終了。其餘官方人工快照保留原查證時間，重建網站不會刷新。詳細限制見[資料查證與品質](資料查證與品質.md)。

每日工作依全站精確作品身分排程，不受卡片原收錄季度限制；沒有可靠資料庫連結者保留待確認。歷史回填與手動重試只在確實需要修復時執行，不為已完成的遷移重跑。

### 基本欄位契約

- `bangumi_id` 是來源 `anime-<數字>` 或受控的 `fallback-<64 位小寫 SHA-256>`；新寫入拒絕歷史 `未知ID`。
- `premiere_date` 表示星期，支援一到日、`一至五`、`不定期公開`、`無首播日期`。不定期與尚未確認分開，來源舊寫法「天」正規化為「日」。
- `premiere_time` 為 `HH:MM`（小時 00–29、分鐘 00–59）或 `無首播時間`；動畫節目表 24–29 時不擅自改為 00–05 時。
- `source_url` 為 `https://acgsecrets.hk/bangumi/YYYYMM/`，月份只允許 01／04／07／10。
- 封面須符合專案的 HTTPS Cloudinary cloud／path 與 `anime_covers/<32 或 64 位小寫雜湊>` 契約。

特殊口徑見[播出範圍查證](broadcast-scopes-2026-10-19/README.md)：耐子週一至五、OniPan! 保留 12 個週合集並顯示週五串流更新，另註電視短篇週一至五；巨神為不定期公開。魚先生保留 12 正篇／6 播出單位，排除＋版；錢天堂維持已播 148、總數與終了未知。無新證據不更動。

## 歷史回填，不上傳封面

先在功能分支執行。預設 dry-run 使用暫存副本，不改正式 JSON、不呼叫 Cloudinary，也不修改來源網站。

```powershell
# 單一作品先檢查
python update_episode_metadata.py --year 2026 --season 春 --anime-id anime-2142

# 寫入單一作品
python update_episode_metadata.py --year 2026 --season 春 --anime-id anime-2142 --write

# 回填全部歷史季度的來源連結，並在預算內補集數
python update_episode_metadata.py --all --write

# 手動核對缺少連結的作品：唯一原名、動畫類型、首播季度及完整條目皆須吻合
python update_episode_metadata.py --all --resolve-missing-links --retry-failed --write

# 剩餘補充資料由之後排程按快取期限及請求預算繼續更新
python generate_static.py
python manage.py validate-all
```

回填只更新原本存在且 ID 相同的資料，保留圖片、名稱、簡介及所有記錄；不新增／刪除動畫。資料更新仍走既有 data PR 與 Quality Gate，不直接推送 main。

## 驗證與回復

命令與本機瀏覽器服務準備統一見[開發與測試](開發與測試.md)。

測試包含 8／12 集、預建集目、同日／未來日期、特殊集、缺日期、錯誤媒體／季別、資料衝突、分頁、限流、失敗保留、快取、舊長篇更新、前端篩選及 360px 手機版。備援測試使用實際《LIAR GAME》頁面的最小結構 fixture，另驗證 API 故障改走頁面、共用預算、端點斷路器、登入／異常頁、過大回應與錯誤原名。

若需回復，回滾功能 PR；已新增的欄位會被舊版嚴格模型拒絕，因此應把同次資料修改一起回復，或使用對應的上一個成功 Cloudflare 部署。不要只回復前端或只回復模型。

手動 `--retry-failed` 只略過失敗查詢的當日快取；成功資料仍遵守原快取期限。`--resolve-missing-links` 預設關閉，不使用模糊配對；缺連結、同名歧義、首播季度不同均保留待確認。月份目錄取得完整分頁後才可用於核對。

手動核對連結時也接受資料庫明列的完全相同別名，完整條目須再次驗證。同一來源卡片 ID、中文名與原名完全相同且只有一個已知 Bangumi ID 的跨季度紀錄，可沿用該 ID 與最近成功快照；不改既有 ID，不複製其他季度的 AniList ID。

已人工核對的來源名稱差異及錯誤／移轉連結保存於 `services/reviewed_episode_identities.json`，僅接受精確卡片、中文名、原名、ID、資料庫正式名與首播日期；其他作品仍使用原有名稱驗證。正常來源解析也會套用已確認的錯誤 ID 修正，避免回填來源舊連結時退回錯誤條目。歷史失敗處理的原始證據與更正見[歷史索引](archive/README.md)。
