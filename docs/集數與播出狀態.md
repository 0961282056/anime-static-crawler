# 集數與播出狀態

動畫卡片新增正篇集數、播出狀態、來源與確認時間；側欄增加播出狀態篩選。範圍是來源所連結的一筆動畫資料庫條目，不是漫畫、真人劇或整個系列。跨季度的同一季仍可共用資料庫 ID。

## 網站顯示

| 資料情況 | 卡片文字 |
|---|---|
| 已播 8 集，確認總數 12 集 | 已播 8／12 集 |
| 已播 8 集，資料庫列預定 12 集 | 已播 8 集／預定 12 集 |
| 未知總數 | 已播 8 集／總集數未定 |
| 完整 12 集且有播畢依據 | 全 12 集 · 本季已播畢 |
| 總數已知但進度不足以判斷 | 共／預定 12 集／進度待確認 |
| 未取得集數 | 集數待確認 · 狀態待確認 |
| 來源更新失敗 | 保留最後確認值，附「更新未成功，資料可能落後」 |

「集數來源與確認時間」可展開查看查詢時間、判斷說明與 Bangumi 正篇集目。未知值使用 `null`，不會用 `0` 代替。

## 資料來源與判斷

- 新番清單、封面、星期、時間與簡介繼續使用 acgsecrets.hk。
- 從來源卡片的資料庫連結讀取 `external_ids.bangumi` 和 `external_ids.anilist`。原本 `bangumi_id` 仍是 acgsecrets 卡片 ID，禁止拿來呼叫 Bangumi API。
- 第一版啟用已實測的 Bangumi API；AniList ID 保存供之後擴充，但本次環境的 AniList 請求被 Cloudflare 阻擋。維基百科、萌娘百科與官方公告目前作人工交叉查證，沒有把混合媒體／多季頁面加入自動回填。
- 查詢 `/v0/subjects/{id}` 與分頁 `/v0/episodes?subject_id={id}&type=0`；驗證條目 ID、動畫類型與來源原名。名稱有歧義時不模糊配對。
- 總集數取 `eps`。`total_episodes` 是資料庫章節數，不能當正篇總數。
- 只計入正篇 `type=0`，依集目 ID 去重，排除非整數集號的回顧篇與特殊集。缺日期／集號斷裂時不把已知下限當精確進度。
- 已播集數依日本日期計算；當日集目尚無可靠播出時刻，暫不計入。這是保守的首播日期進度，可落後一天，不代表台灣平台上架進度。
- 「本季已播畢」需同時有：已過的明確結束日期、完整正篇清單、所有正篇日期已過，以及正篇數等於總話數。集數相等本身不代表播畢。
- 播出中依未來集目／近期尚未完成的集目判斷。缺乏足夠證據時使用未知；暫停和取消狀態保留於模型與介面，但不從停止更新推算。
- 預定集數在完整播畢核對前顯示「預定」。本季播畢不等於全系列完結。

Bangumi API 契約：https://github.com/bangumi/api/blob/master/open-api/v0.yaml

## 保存與更新

`Anime` 新增 `original_name`、`external_ids` 及可空的 `episodes`；舊季度 JSON 可繼續讀取。集數欄位集中在 `episodes`，包含總數、已播、狀態、計數狀態、查詢狀態、來源 URL、成功確認時間、嘗試時間與結束日期。

爬取基本資料後會合併同一卡片 ID 的舊集數；如果外部動畫 ID 改變，就清除舊補充資料重新確認，避免套用到另一季。補充來源失敗、資料缺漏或進度倒退不會覆寫最後有效值；來源衝突會標示待核對。

一般作品每天重查；結束後第一週每天重查，之後每 30 天確認一次。季度 JSON 本身就是持久快取，不依賴臨時 runner 檔案。單次預設最多 240 個 API 請求、最多 5 分鐘、每頁 200 筆且最多 20 頁；請求間隔至少 0.5 秒。429、5xx 或連線錯誤會停止該次來源請求，其他作品保留原資料，下一次更新再試。

每次正常爬蟲會刷新全站已連結的作品，因此較早季度的長篇作品仍能更新。新季度的外部 ID 由現有爬蟲自動取得；尚未有外部 ID 的舊季度需要執行下列一次性回填。沒有資料庫連結的作品保留待確認，不以名稱搜尋結果直接猜配。

## 歷史回填，不上傳封面

先在功能分支執行。預設 dry-run 使用暫存副本，不改正式 JSON、不呼叫 Cloudinary，也不修改來源網站。

```powershell
# 單一作品先檢查
python update_episode_metadata.py --year 2026 --season 春 --anime-id anime-2142

# 寫入單一作品
python update_episode_metadata.py --year 2026 --season 春 --anime-id anime-2142 --write

# 回填全部歷史季度的來源連結，並在預算內補集數
python update_episode_metadata.py --all --write

# 剩餘補充資料由之後排程按快取期限及請求預算繼續更新
$env:BUILD_ONLY = "true"
python generate_static.py
python manage.py validate-all
Remove-Item Env:BUILD_ONLY
```

回填只更新原本存在且 ID 相同的資料，保留圖片、名稱、簡介及所有記錄；不新增／刪除動畫。資料更新仍走既有 data PR 與 Quality Gate，不直接推送 main。

## 驗證與回復

```powershell
python -m pytest
python -m ruff check .
python -m ruff format --check .
npm run test:frontend
npm run test:e2e
```

測試包含 8／12 集、預建集目、同日／未來日期、特殊集、缺日期、錯誤媒體／季別、資料衝突、分頁、限流、失敗保留、快取、舊長篇更新、前端篩選及 360px 手機版。

若需回復，回滾功能 PR；已新增的欄位會被舊版嚴格模型拒絕，因此應把同次資料修改一起回復，或使用對應的上一個成功 Cloudflare 部署。不要只回復前端或只回復模型。
