# 開發與測試

本頁集中維護本機安裝、建置與測試命令。平台設定見[部署手冊](部署與平台設定.md)，元件與目錄見[架構與資料流](架構與資料流.md)。

## 安裝環境

需要 Git、Python 3.11；前端及瀏覽器測試另需 Node.js 20 以上。Windows 使用 PowerShell，執行 `build.sh` 時需 Git Bash 或 WSL。先同步最新 `main`，再建立功能分支。

Linux／macOS／Git Bash：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes -r requirements-dev.txt
npm ci
```

Windows PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --require-hashes -r requirements-dev.txt
npm ci
```

若 PowerShell 阻擋啟用，不必降低全機安全設定；可直接使用 `.\.venv\Scripts\python.exe` 執行命令。

| 依賴檔 | 用途 |
|---|---|
| `requirements-build.txt` | Cloudflare 只建置網站的最小依賴 |
| `requirements-canary.txt` | 唯讀來源檢查，含 HTML parser，不含 Cloudinary／Pillow |
| `requirements.txt` | 正式爬蟲 |
| `requirements-dev.txt` | 開發、測試與品質工具 |
| `*.in` | 直接依賴來源；安裝使用有 hash 的 `*.txt` |
| `package-lock.json` | Node 測試工具鎖定版本，使用 `npm ci` 安裝 |

依賴升級應重新產生 lock 並驗證，不手動改 hash 讓安裝通過。CI 的完整命令以 [ci.yml](../.github/workflows/ci.yml) 為準。

## 只建置網站

此模式讀取既有季度 JSON，不爬來源、不操作 Cloudinary，也不需要 `.env`。

```bash
BUILD_ONLY=true python generate_static.py
python manage.py validate-all
```

PowerShell：

```powershell
$env:BUILD_ONLY = "true"
python generate_static.py
python manage.py validate-all
Remove-Item Env:BUILD_ONLY
```

`bash build.sh` 是 Cloudflare 正式入口，會安裝 `requirements-build.txt` 並強制只建置。完成後應有首頁、搜尋索引、版本清單、安全標頭與靜態資產；`validate-all` 驗證所有季度資料、資產與發布清單一致。

`dist/data/` 是正式資料；其餘 `dist/` 輸出由建置產生。不可為了清除產物刪除整個 `dist/`。Windows 短暫鎖住 `dist/static` 時有有限重試，耗盡仍安全失敗並保留原輸出；先關閉占用程式，再重新建置。

## 修改前端

瀏覽器程式的模組來源在 `frontend/`，模板在 `templates/`，CSS 與其他資產在 `static/`。

```bash
python manage.py build-frontend
npm run test:frontend
BUILD_ONLY=true python generate_static.py
```

`static/js/main.js` 是受 Git 追蹤的生成檔，須與模組一起提交。建置會檢查它是否過期；不要只改生成檔。Alpine 使用本站固定版本的 CSP build，升級 vendor 時需核對 integrity、SHA-256 與 license，再驗證安全測試及瀏覽器。

## 執行測試

```bash
python -m pytest
python -m ruff check .
python -m ruff format --check .
python manage.py validate-all
npm run test:frontend
```

`validate-all` 前須完成建置。Windows 專用檔案權限／替換測試在 Linux 略過，由原生 Windows CI 實測。工作流程與 shell 另由 CI 的 actionlint／ShellCheck 檢查。必要 `quality` 彙總 Linux 與 Windows，兩者成功且跨工作 artifact 驗證通過才可合併；自動依賴更新及 CDN 盤點見[維護手冊](依賴與Actions維護.md)。

瀏覽器回歸先安裝 Chromium：

```bash
npx playwright install chromium
```

先完成只建置，再於另一個終端機啟動本機服務：

```bash
python -m http.server 4173 --bind 127.0.0.1 --directory dist
```

回原終端機執行 `npm run test:e2e`。測試涵蓋資料載入、搜尋／篩選、季度切換、快取與儲存失敗、簡介與分享清單的鍵盤操作。Linux CI 以 `npx playwright install --with-deps chromium` 安裝系統依賴；跨瀏覽器擴充仍是[後續計畫](CSP與跨瀏覽器改善計畫.md)。

## 效能與穩定性複查（2026-10-21）

由 main `98bc43d782dd08ea4fc3ca50ff1b8a2577083a57` 接續檢查，覆蓋瀏覽器搜尋／共用請求／匯出、靜態建置，以及既有爬蟲失敗保留、快取與原子寫入測試。下表是本地隔離情境，不是正式訪客統計或耗電量測：

| 情境 | 修正前觀察 | 修正後行為 |
|---|---|---|
| 360px、CPU 降速 4 倍，以真實資料搜尋「的」，圖片換成本地測試 PNG | 1,560 張卡片、82,453 個 DOM 節點；單次搜尋約 17.45 秒，情境最長 long task 約 16.62 秒。 | 總數仍為 1,560，先顯示 60 張、3,358 個 DOM 節點；相同設定一次測量約 1.96 秒、最長 long task 約 1.12 秒。另一次帶正式 CSP 的可重現工具量測約 1.76 秒、0.88 秒，JS heap 約 38 MiB。這些單次結果不代表所有裝置的改善比例。 |
| 快速更換查詢，各有 4 個慢速季度請求 | 舊查詢繼續下載，同時請求增加到 8；不同 scope proxy 可把同一請求送出 2 次。 | 同情境最多 4 個；共用請求 1 次。最後一位訂閱者取消就中止下載，仍有人需要時保留。搜尋失敗也取消其他 worker，遲到回應不重填快取。 |
| 分享等待／清單修改 | 字型、渲染、toBlob／剪貼簿可無限等待；完成後直接清空整張清單，包含後來加入的項目。 | 分段設限、復原 UI／清理 DOM；匯出使用快照，只移除該批項目；阻擋重複開始與遲到 callback。代碼與期限見[錯誤診斷](錯誤診斷與重試.md#前端資料錯誤)。 |
| 大型分享清單 | 沒有項目／畫布資源上限，固定 3 倍渲染。 | 下載封面前先拒絕超過 20 部；依實際尺寸限制畫布至約 1,600 萬像素、單邊 16,384，倍率最多 3、至少 1，仍過大則提示分批。這只是單張 canvas 的約束，不是整個分頁記憶體上限。 |
| 本地 BUILD_ONLY | 未開 profiler 的 3 次中位數約 0.67 秒，最大子程序 RSS 約 43 MiB；cProfile 顯示 37 個季度檔共載入 148 次，重複驗證佔主要 CPU 成本。 | 本批保留驗證門檻；共用經驗證快照列為較低優先改善。此結果不含正式爬蟲、來源網路或圖片上傳耗時。 |

全站搜尋只限制一次建立的卡片數，完整結果仍參與放送日／狀態篩選，不只篩第一批；「顯示更多」每次增加 60 筆，鍵盤操作會把焦點移至新加入的第一張卡片。所選單一季度維持完整顯示。大量搜尋仍可能需要讀取全部匹配季度的 metadata；縮小此網路量需要另外設計索引欄位與完整篩選契約。

重現量測：先執行 BUILD_ONLY 建置並在另一終端機依上節啟動 `127.0.0.1:4173`，再執行 `node scripts/profile-frontend.mjs`。工具只量測本地站、使用正式 CSP、360px／4 倍 CPU 情境，將封面替換為合成 PNG，不連來源爬蟲或操作 Cloudinary；仍需讀取正常的 CDN CSS／JS。結果寫入忽略的 `audit-output/frontend-profile.json`，包括瀏覽器版本、結果／DOM 數、時間、long tasks 及 JS heap。若使用本機 Chromium，可設定 `CHROMIUM_EXECUTABLE`；一般 Playwright 安裝後可直接執行。

回歸包含取消／共用／scope proxy／失敗 worker／遲到回應、完整篩選及分批顯示、分享超時／畫布限制／新增項目保留，以及正式 CSP 下的真實 Chromium fetch 取消、UI 復原與鍵盤展開。時序測試不設定機器速度門檻。未實測 Firefox／WebKit、真實手機電池或現場網路；第三方渲染／剪貼簿無取消 API、後端 socket timeout 不等於嚴格整段傳輸期限，仍依[後續順序](後續工作順序.md)處理。不寄信、不發測試通知、不建假 Issue、不手動觸發排程，也不為驗證修改 Cloudinary。

## 查資料品質

| 命令 | 用途／外部影響 |
|---|---|
| `python manage.py validate-data` | 離線驗證季度 JSON |
| `python manage.py verify-dist` | 離線比對建置資產、搜尋索引與發布清單 |
| `python manage.py quality-report` | 離線列出缺漏、查證狀態與更新到期情況 |
| `python manage.py quality-evidence` | 離線建立可追溯證據與品質歷史，輸出到忽略的 `audit-output/quality/` |
| `python manage.py source-audit` | 連線唯讀核對季度與來源；不修改公開資料，AniList API 預設停用 |

查證、時間欄位、審核回覆及引用規則統一見[資料查證與品質](資料查證與品質.md)。執行失敗先讀[錯誤診斷與重試](錯誤診斷與重試.md)。

## 確實需要執行本機爬蟲時

依 `.env.example` 建立忽略的 `.env`，填妥必要憑證。`python generate_static.py` 在未設定 `BUILD_ONLY=true` 時會抓來源、上傳必要封面並更新資料；執行前先依部署及安全手冊確認備份與授權。

提交前用 `git status --short`、`git check-ignore .env`、`git diff --cached --check` 檢查，不提交 `.env`、秘密或忽略的建置產物。變更經 PR 檢查、合併及正式站驗收；不為驗證建立假 Issue、發測試通知、手動觸發排程或變更 Cloudinary。

歷史 `未知ID` 遷移已完成，不列入日常命令；舊步驟可由[歷史索引](archive/README.md)追查。
