# 資料來源交叉核對與複查

這項改善將例行查證交給系統：每週核對所有已收錄季度、建立官方人工快照複查清單，並用 AniList 作為獨立的第二資料來源。公開集數與播出狀態仍由既有流程更新；新流程產生可追查的報告。

## 使用方式

```bash
python manage.py source-audit
```

預設產生 `audit-output/source-audit.json` 與 `source-audit.md`，目錄已忽略。可用 `SOURCE_AUDIT_OUTPUT` 指定目錄，但不能設於公開 `dist` 內。需要 `requirements-canary.txt` 的既有依賴，不需要 Cloudinary 或 AniList 金鑰。

合併後，GitHub Actions 的 **Weekly Source Coverage and Cross-check** 每週一台北時間 10:30 執行，也可手動執行。Actions Summary 顯示摘要，完整 JSON 放於 `source-audit-<run_id>` artifact，保留 30 天。沒有新增 Discord／電子郵件通知。

## 前後差異與處理規則

| 項目 | 原本 | 改善後 |
|---|---|---|
| 歷史季度 | 一般爬蟲主要更新近期季度 | 每週讀取所有本地已收錄季度的來源頁面，列出漏收、消失、改名、播出欄位與明確外部 ID 差異 |
| 人工快照 | 查證時間與範圍存在備註，需逐筆翻閱 | 依精確作品身分去重，未完結／未知每 7 天、已完結每 90 天排入複查清單；跨季副本取最舊成功查證時間 |
| 第二來源 | Bangumi API 與 Archive 能互相備援，但資料系譜相同 | AniList 獨立核對作品身分、類型、預定總數及狀態；不推算已播集數 |
| 資料來源紀錄 | 部分方法、範圍在自由文字 | 每份報告逐筆列出 provider、scope、來源網址、成功查證、最後嘗試、未知欄位與原始備註 |
| 簡介等缺漏 | 無法從統計分辨為何缺少 | 報告區分來源本來缺少、來源有但尚未匯入、這次無法取得對應來源 |

季度來源必須全部卡片可解析且 ID 不重複，才進行該季集合比較。任何一張解析失敗，整季標示錯誤，避免把解析失敗當成作品刪除。即使來源真的不再列出作品，也只列為待查證，不自動刪除。

季度核對每頁只嘗試一次，沿用 15 秒預設請求逾時，整個季度階段預算 600 秒；預算用完後，其餘季度標示未完成並保存報告。這與每日爬蟲的重試和集數更新預算分開，避免每週檢查影響正式資料更新。

季度比對使用已審查過的 parser，所以既有明確的 Bangumi ID 修正仍有效。它核對的是經既有規則處理後的來源，不是完全獨立的第二解析器。

AniList 只使用資料中已有、或當次季度頁面明確提供的連結。不進行名稱模糊搜尋。從來源補取連結時，卡片 ID、中文名、原文名、Bangumi ID 必須完全符合既有身分；同一作品跨季出現不同 AniList ID 時直接列為衝突，不任選一個。新找到的連結僅存在報告，不改寫公開資料。

核對會檢查原文名稱（僅正規化全半形、空白與大小寫，保留季數及副標題）、動畫類型及播出日期。TV／TV_SHORT 才進入數字比較，其他形式先檢查範圍。名稱、類型、日期有問題，或作品已有官方特別範圍審查，均不直接比較或採用其數字。總數與狀態一致只代表互相佐證，不能單憑一致便證明 TV、網路版、分割季度及特別篇範圍相同。

每次最多 30 個 AniList HTTP 請求、每批 40 個明確 ID、請求起點至少間隔 1 秒，第二來源階段預算 180 秒；單次連線／讀取逾時 5／20 秒，最後一個請求可能跨過階段預算。拒絕重新導向；遇 429、錯誤 HTTP、GraphQL 局部錯誤或不符契約回應即停止後續批次，保留已完成的觀察。後續未送出批次標示未嘗試，不冒充查證失敗或成功。

來源取得失敗時，報告保留其他成功季度／批次，失敗項目的成功查證時間為空；命令以非零狀態結束，Actions 仍保存部分報告。正常的資料差異不令命令失敗。此流程不刷新既有資料的 `checked_at`。

## 需要人工判斷的界線

維護者可先處理名稱格式、來源暫時失敗及既有範圍規則；使用者不需要逐筆審查報告。只有找不到既有規則可解釋的作品身分或集數範圍爭議，才整理「目前值、來源值、證據、建議」提出討論。

人工快照的複查期限是維護政策，不表示期限內必然最新。這版建立清單，尚未新增 NHK 等官方頁面的自動抽取器；重跑本報告不會重新驗證這些快照。

## 保留的限制

- 只檢查本地已收錄季度，不探索未知季度，也不證明原季度來源本身沒有漏作品。
- 沒有明確 AniList 連結的作品不進行第二來源查詢；總數不一致不會自動選較大值。
- 結構化來源資料儲存在報告，公開 JSON 格式不變。舊資料無法確定 API／HTML／Archive 方法或來源快照日期時明確留空並保留備註；不把本次報告時間當作原始資料日期。
- AniList 的未來排程不等於已播證據；不從下一集時間或總集數推算已播進度。
- 報告只提供觀察，尚未提供公開網站的來源詳情 UI，也不自動補寫缺漏的簡介或外部 ID。
