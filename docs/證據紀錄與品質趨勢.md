# 證據紀錄與品質趨勢

`python manage.py quality-evidence` 唯讀產生 `audit-output/quality/`，不請求外部來源、不需要 Cloudinary 或通知憑證。main 更新後的 **Quality Evidence and Trends** 工作會自動執行，artifact 保留 90 天。

## 統一證據格式

離線品質報表及每週來源核對都輸出 schema_version=1 的 `evidence.json`。每筆包含精確卡片／中文名／原名／Bangumi 身分、季度、欄位、來源網址、取得方法、計數範圍、內容 SHA256、原始檔 JSON pointer 及可重現的 evidence_id。

| 狀態／時間 | 意義 |
|---|---|
| observed / checked_at | 本次來源核對有成功觀察；比對有差異仍可為成功觀察，不表示資料應改寫 |
| failed / attempted_at | 本次確實開始請求但沒有完成查證，checked_at 為空 |
| not_attempted | 預算耗盡等原因未開始請求，不產生嘗試或成功時間 |
| retained / last_verified_at | 沿用公開資料已記錄的證據，不是本次重新查證 |
| unrecorded | 來源方式、日期或範圍未記錄，維持未知 |
| assembled_at | 整理檔案時間，不是查證時間 |
| source_snapshot_at | 原資料明確記錄的快照日期，沒有則留空 |

內容指紋針對 JSON 正規化後的欄位／比對結果；季度核對的 document_sha256 則是取得的 HTML 文件指紋。兩者不冒充已保存的原始 HTTP 回應。完整內容依 locator 回看同 artifact 的 source-audit.json，或 bundle.commit 指定的 dist/data 檔案；舊有人工證據文件仍是原始證據，不把整理日倒填為查證日。

每週核對仍是唯讀，既有通知工作不因新格式增加權限或改寫公開資料。來源失敗時，保留的 primary 舊成功時間與本次失敗／未嘗試分列。

## 品質歷史

`quality-trend.json` 從 Git 的 main 第一父系資料變更版本重建，依提交順序，保存每版原始數量與分母比率；`recorded_at` 是提交時間，不是來源查證時間。預設最近 120 個資料版本，可用 `QUALITY_HISTORY_LIMIT=1000` 擴大。截斷、淺層 clone、不相容版本都明列，不能當成完整歷史。

度量季度記錄而非推測去重作品：簡介／首播日／Bangumi／AniList 缺漏、集數 stale／conflict、未記錄取得方法或成功查證時間。`working_tree.issue_records` 可按季度及精確作品身分查缺漏；`change` 僅比較兩版相同身分，改名、換 ID、新增或移除另計，避免刪除作品被算成「修好」。沒有集數資料的舊版本視為查證時間缺漏，方法未知則只計已有集數欄位者。

`quality-trend.svg` 可直接以瀏覽器開啟，顯示簡介、AniList、集數查證時間的缺漏率；原始 JSON 含所有八項度量。artifact 到期後，完整 Git 歷史仍可重新產生。早期空季度保留為零筆；歷史結構無法讀取或身分重複會明列跳過，不套用今天的驗證或來源方法回寫舊資料。

2026-10-19 本地驗收：37 季／2,150 筆、120 個資料版本、零不相容版本；簡介缺漏 105、首播日 5、Bangumi 1、AniList 1,378。這是資料完整性現況，不是新來源核對結果。Python 577 通過／2 個 Windows 本地略過，工作流程語法檢查通過；正式執行紀錄於本批 PR 合併後補記。
