## 原文、範圍與限制

[證據](evidence.json)保留精確卡片、中文名、原名、既有 BG ID、來源原文短節錄、取得時間與 SHA256，並列出兩個實際 BG 目錄的編號、日期、片長。兩筆原來源註記逐字包含比對，非由宣傳文自行推論。四筆公開日是結構欄位摘錄，不是新增故事簡介。

[實際請求](access.json)包含本次三季原來源 HTTP 200、兩次 BG 目錄最初 HTTP 403（提供者明示拒絕 HTTP 函式庫預設 User-Agent），改用專案既有具名 User-Agent 後兩筆 HTTP 200。認證、代理與 TLS 均保留，非繞過網路規則。東京電視台兩個候選舊節目表 HTTP 404；NCC 舊動畫入口 HTTP 308 導向首頁，未當作可用官方正文；搜尋結果與查詢無關，未採用。

本次實際環境 revision 106 與 observed revision 106 一致，observations_current=true、network=enforced。未請求已知不允許的 onipan／TOKYO MX／DLE 等域名，未變更設定。之前 BG 條目的放送星期只作既有觀察的佐證，沒有把重讀快取當成新 HTTP 成功。

## 顯示與防護

- 新增 `一至五`、`不定期公開` 的明確合法值，保留原有單日及未知值。單一平日篩選會納入平日連播，週六／週日不會納入；另可單獨選多日、不定期或待確認。
- 卡片直接顯示播出方式與範圍說明、可點擊的出處；不定期與未知分開，不藏在集數詳細資訊中。OniPan! 以週五合集篩選，電視每日短篇另以文字說明。
- 同一份 `reviewed_broadcast_sources.json` 產生前端說明，不另手寫第二份身分清單。卡片／中日文名稱／BG ID／星期任何一項不符，前端不附加其他版本的說明或來源。
- 來源再次缺時間欄位時，資料庫恢復精確身分後保留已查證星期；首次寫入與更新都拒絕相衝突的星期。來源換作品須重新核對規則。解析器只接受明示排程，未支援的多日範圍不會被截成第一天，空白／時間未定不會自動變成不定期。
- 播出來源說明納入應用版本雜湊；只改說明也會更新快取版本。集數、已播數、播出狀態及所有集數來源時間均未修改。
