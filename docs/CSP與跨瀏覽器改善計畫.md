# CSP與跨瀏覽器改善計畫

建立：2026-10-20；程式基準PR #71／`42f3c86`。本文件安排後續實作，**尚未修改CSP標頭、前端樣式、Playwright矩陣或CI**。有效待辦與其他優先事項見[後續工作順序](後續工作順序.md)。

## 現有基準

`_headers`的script-src已不含unsafe-eval，Alpine使用本站固定版本的CSP build；style-src仍允許unsafe-inline。來源包含`templates/index.html`的style屬性、`frontend/sharing.js`的動態匯出樣式，以及SweetAlert2彈窗／提示的樣式行為。不能只刪一個CSP關鍵字就宣稱完成。

`playwright.config.js`目前只有Chromium專案；部分案例調整至360px手機viewport，代表小螢幕排版驗收，不等同Safari、WebKit或真實iOS裝置測試。CI只安裝Chromium，正式瀏覽器驗收腳本也明確使用Chromium。

## 階段1：CSP盤點與樣式重構

建議獨立PR，先不收緊正式標頭：

1. 盤點模板style屬性、JavaScript的style／cssText、第三方元件注入的style元素或屬性。區分固定樣式、執行期CSSOM設定與真正需要動態產生的值；以實際CSP違規事件與畫面驗收判斷，不僅靠字串搜尋。
2. 將固定版面與分享匯出樣式移入`static/css/main.css`，以class切換；檢查Alpine的x-show／隱藏狀態、載入／錯誤提示及SweetAlert2的實際相容性。若需更換第三方樣式包，先核對版本、固定雜湊與授權，再測試。
3. 在測試頁套用候選CSP，捕捉securitypolicyviolation與JavaScript錯誤；逐步驗證正式頁及html2canvas的複製／匯出文件，不把測試伺服器沒有回傳CSP誤當通過。

完成標準：一般查詢、空狀態、錯誤重試、資料來源／維基署名彈窗與分享清單外觀保持可用；分享能輸出有效PNG，圖片載入／渲染失敗後按鈕與暫存容器恢復。來源顯示、JSON與Cloudinary資產值不因樣式重構變動。既有測試適當通過並完成差異審查。

## 階段2：收緊正式CSP

階段1通過後另開PR，才評估移除style-src中的unsafe-inline。對style-src-elem／style-src-attr採用的實際政策、外部CSS與字型來源逐項說明；只保留實際需要的來源，不加入萬用字元、unsafe-eval或額外寬鬆規則補救測試失敗。

若靜態網站採hash等方案，須把穩定產物、每次建置的生成方式與更新驗證一併實作；不使用固定公開nonce假裝每次請求的新nonce。無法收斂的第三方行為應記錄具體限制與後續選項，不將仍保留的例外寫成「已全面移除」。

驗收需同時包含：實際正式標頭、候選政策下的瀏覽器行為、CSS／腳本載入、分享成功與失敗恢復、來源署名連結、Cloudflare分析beacon，以及發布清單中的全部公開檔案與該版本一致；檔案數依該批建置，不固定沿用舊數字。若尚未完成前置重構，維持現有政策並明確記為未完成。

## 階段3：擴充瀏覽器引擎

以階段2的穩定政策為基準再開獨立PR；若CSP階段仍有未解限制，先記錄基準與原因，不混合兩種失敗歸因。

| 驗收層次 | 計畫範圍 | 完成標準 |
|---|---|---|
| 桌面引擎 | Chromium、Firefox、WebKit | 載入／篩選／全季搜尋、切季競態、快取與儲存失敗、資料與維基署名、彈窗、分享下載及錯誤恢復全部有實際結果。 |
| 小螢幕排版 | 三引擎各含代表性360px viewport | 無水平溢出，篩選、來源與署名可讀；另檢查鍵盤可聚焦操作，不能只縮放截圖。 |
| 真實裝置 | 後續可用的Safari／iOS、Android Chrome | 紀錄裝置、作業系統、瀏覽器版本與手動步驟；沒有裝置就列未實測，不由Playwright WebKit推定真機通過。 |

先核對現有22項測試的引擎相依條件，再擴充`playwright.config.js`、CI安裝範圍與報告，控制在既有job期限內；若需分job，required gate必須涵蓋各引擎，不讓選用job失敗仍被宣稱整體通過。結果依引擎分列，不預先把22乘3當已通過數量。

剪貼簿支援、權限與使用者手勢條件有差異；測試應驗證可用時的複製，以及不可用／拒絕時的明確訊息與下載備案，不為綠燈任意skip功能。圖片匯出至少驗證檔案格式、內容尺寸與非空畫面，故障模擬使用本地fixture，不更動Cloudinary。正式驗收也須明示實際用了哪些引擎。

## 每階段的證據與完成紀錄

每個PR記錄最終範圍、CSP或引擎差異、必要測試、PR／main檢查、預覽與正式驗收連結。只更新實際完成的階段；其餘留在有效待辦。適用的功能修正須有針對性回歸，文件整理本身不新增鏡像實作的測試。全程保留既有網路規則、代理、TLS、認證與資料範圍；安裝來源受限時如實列限制，不換路徑繞過。
